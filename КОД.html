3. Модуль database.py НОВОЕ в v2.2.0

3.1. Назначение

Слой работы с SQLite. Отвечает за создание базы данных и таблиц, получение соединения, инициализацию при первом запуске.

Зависимости: sqlite3, os.

def reset_db() -> None

Что делает: полностью удаляет файл БД.

Это сердце программы — решатель расписания на базе OR-Tools CP-SAT.

Зависимости: models.py, ortools.sat.python.cp_model.

5.2. Константы

КонстантаЗначениеЧто значит
DAYS5Количество учебных дней (Пн–Пт)
SLOTS_PER_DAY8Количество уроков в день
MAX_SLOTS40Всего слотов в неделю (5 × 8)
Изменение v2.2.0: SLOTS_PER_DAY = 8 (было 7), MAX_SLOTS = 40 (было 35).

5.3. Класс Scheduler

class Scheduler: def __init__(self, teachers, classes, subjects, rooms):

Что делает: принимает списки объектов из models.py и сохраняет их в словари по id для быстрого поиска.

5.4. Метод _precheck()

def _precheck(self) -> str:

Что делает: быстрая проверка — возможно ли вообще составить расписание. До запуска OR-Tools.

Проверяет:

№Проверка
1Сумма часов класса ≤ 40
2У каждого предмета с часами есть учитель
3Есть хотя бы один кабинет

5.5. Метод _find_teacher_for_class() НОВОЕ в v2.2.0

def _find_teacher_for_class(self, subject: str, class_name: str):

Что делает: ищет учителя для конкретного класса. Сначала смотрит в Subject.teachers (привязка «класс → учитель»), если нет — берёт первого, кто ведёт предмет.

Зачем: чтобы математику в 5А вёл Петров, а в 6А — Соколов.

5.6. Метод _find_rooms_for()

def _find_rooms_for(self, subject: str, class_name: str) -> List[int]:

Что делает: возвращает список подходящих кабинетов: сначала специализированные, потом обычные.

5.7. Метод solve() — главный метод

def solve(self) -> tuple[bool, str]:

Что делает: составляет расписание через OR-Tools CP-SAT.

Возвращает: (True, "OK") при успехе или (False, "сообщение") при ошибке.

Ограничения модели:

ОграничениеЧто гарантирует
Каждый урок — ровно в одном слотеНет «потерянных» уроков
Класс / день / слот: сумма ≤ 1Нет двух уроков у класса одновременно
Учитель / день / слот: сумма ≤ 1Учитель не ведёт два урока одновременно
Класс / предмет / день: сумма ≤ 2Не более 2 уроков одного предмета в день
Запрещённые слоты: x = 0Учитель не ведёт в запрещённое время

Параметры решателя:

solver.parameters.max_time_in_seconds = 10.0
solver.parameters.stop_after_first_solution = True
solver.parameters.num_search_workers = 8
Изменение v2.2.0: добавлено ограничение «не более 2 уроков предмета в день», лимит 10 секунд, stop_after_first_solution = True.
⚠️ Распределение кабинетов: происходит после решения CP-SAT — жадно, с приоритетом специализированных. Если в слоте все кабинеты заняты — берётся первый попавшийся (это может дать накладку — см. проверку в desktop_app.py).

Зависимости: только стандартные (никаких внешних библиотек).

7. Модуль substitutions.py НОВОЕ в v2.2.1

7.1. Назначение

Поиск замен для урока. Простейшая версия — в памяти, без БД.

Зависимости: ничего (работает с data и schedule).

7.2. Функция find_substitutes()

def find_substitutes(data, schedule, day, slot, class_name, subject, original_teacher_id)

Что делает: возвращает список кандидатов на замену.

Критерии:

  1. Ведёт этот предмет (есть в списке subjects).
  2. Свободен в этом слоте (нет своего урока).
  3. Слот не в unavailable_slots.
  4. Не ведёт уже урок в этом классе в этот день (пометка «уже в классе», не блокирует).

Ранжирование: по нагрузке (меньше — лучше) и штрафу за «уже в классе».

Ограничение: замены хранятся в памяти и сбрасываются после перезапуска программы.

9.4. Главная функция import_from_excel(filepath)

def import_from_excel(filepath) -> tuple[bool, str]:

Что делает: читает Excel → пишет в SQL → возвращает отчёт.

Пошагово:

  1. Читает Excel через read_excel.
  2. Открывает соединение с БД.
  3. Очищает таблицы: lesson_plan, teacher_subjects, teacher_unavailable.
  4. Импортирует по порядку: школа → предметы → классы → кабинеты → учителя → учебный план.
  5. Коммитит и возвращает отчёт: сколько учителей, предметов, классов, кабинетов, строк плана.
Важно: импорт очищает lesson_plan, teacher_subjects и teacher_unavailable перед записью. Данные о школе, учителях, классах, предметах, кабинетах — обновляются (не удаляются).

13.4. Проверка накладок кабинетов НОВОЕ в v2.2.1

В build_schedule после scheduler.solve():

  1. Проходит по editable_schedule.
  2. Строит словарь busy_rooms_check[(day, slot, room_id)].
  3. Если ключ уже есть — это накладка: два класса в одном кабинете.
  4. Формирует room_conflicts — список строк с деталями.
  5. Выводит зелёную плашку «Кабинеты в порядке» или красную с количеством и списком.

14.2. Поток данных при составлении расписания

  1. Пользователь нажимает «Составить расписание».
  2. desktop_app.build_schedule() вызывает advisor.analyze(data).
  3. Если есть ошибки — выводятся пользователю, стоп.
  4. Конвертирует dict → объекты (Teacher, SchoolClass, Subject, Room).
  5. Создаёт Scheduler(...) и вызывает solve().
  6. Scheduler.solve() строит модель CP-SAT и решает.
  7. Возвращает список Lesson.
  8. desktop_app проверяет накладки кабинетов и отображает расписание.
  9. Пользователь может перемещать уроки (клик-клик) или назначить замену (🔁).
  10. При экспорте — excel_export.export_to_excel() создаёт .xlsx.

14.3. Поток данных при импорте из Excel

  1. Пользователь нажимает «📥 Импорт из Excel» на Шаге 6 мастера.
  2. desktop_app.do_import() вызывает excel_import.import_from_excel("template.xlsx").
  3. read_excel читает 6 листов.
  4. import_school, import_subjects, import_classes, import_rooms, import_teachers, import_lesson_plan пишут в SQLite.
  5. Возвращается отчёт.
  6. desktop_app показывает snackbar и перерисовывает вкладки.

14.4. Поток данных при активации

  1. При запуске desktop_app.main() вызывает license.is_activated().
  2. license.load_license() читает license.json из APPDATA/LOCALAPPDATA.
  3. Если ключ есть и валиден — полная версия.
  4. Если нет — демо-версия с баннером.
  5. Пользователь нажимает «🔑 Ввести ключ».
  6. license.is_valid_key() проверяет ключ (перебор до 100000).
  7. license.save_license() сохраняет ключ в оба пути.

15. Ключевые технические решения

15.1. Почему OR-Tools, а не backtracking

КритерийBacktrackingOR-Tools CP-SAT
Скорость (7 классов)минутысекунды
Скорость (20 классов)часы / зависание10–60 секунд
Оптимизацияне умеетумеет (минимизация окон)
Параллелизмнетда

15.2. Почему SQLite, а не JSON НОВОЕ в v2.2.0

  • Надёжность — транзакции, целостность, внешние ключи.
  • Скорость — индексы, быстрый поиск.
  • Масштабируемость — можно хранить тысячи записей.
  • Один файл — school.db, легко перенести.
  • Минус: нельзя править вручную, как JSON.

15.3. Почему офлайн-проверка ключа

  • Нет сервера — не надо платить.
  • Работает без интернета.
  • Быстро — проверка за миллисекунды.
  • Минус: ключ можно вычислить, если знать соль.

15.4. Почему Flet, а не Tkinter

КритерийTkinterFlet
Внешний видустаревшийсовременный
КроссплатформенностьWindows/Linux/Mac+ Android/iOS/Web
Сложность вёрсткивысокаянизкая
Размер .exe~20 МБ~150 МБ
Компромисс: Flet даёт красивый UI и кроссплатформенность, но .exe больше из-за встроенного движка Flutter.
